# Native providers (Claude Code, Codex CLI, opencode CLI, Fake)

Run each stage through the locally installed `claude`, `codex`, or `opencode` executable with its own authentication and configuration, or through the deterministic Fake provider for tests.

## Sub-features
- claude: non-interactive stream-JSON print mode, `dontAsk` permissions, prompt on immutable stdin; denied tools become typed permission attention; questions (`AskUserQuestion`) need `--response`.
- claude-baseline-allowlist: every Claude invocation starts from a fixed baseline (`BASELINE` in `src/providers/claude/permissions.rs`) whatever the repository says — reading the tree (`grep`, `rg`, `find`, `ls`, `cat`, `head`, `tail`, `sed`, `awk`, `cut`, `tr`, `sort`, `uniq`, `wc`, `diff`, `jq`, `echo`, `printf`, `basename`, `dirname`) plus the reporting-only `git` subcommands (`status`, `log`, `show`, `diff`, `grep`), and changing it (`Edit`, `MultiEdit`, `Write`). Nothing that installs, builds, runs a package script or reaches the network is in it: `yarn`, `npm`, `npx`, `node`, `python3`, `gh` and the rest stay a per-repository decision. Without this every run in every repository re-paid the same denials before it could look at anything.
- claude-repo-allowlist: the `[permissions] allow` table of `<worktree>/.senate.toml` — or of `<source repo>/.senate.toml` when the worktree carries no such file — becomes `--allowedTools` on every Claude invocation, initial and resumed, beside the baseline above and anything a resolved attention granted. Rules are native Claude Code rules, passed through verbatim; a rule that grants every tool (`*`, `Bash(*)`) or an empty one fails the stage.
- codex: `codex exec --json` with prompt `-` on stdin, `--ask-for-approval never`, sandbox `read-only` for non-mutating stage kinds and `workspace-write` for Implementation/Fix/FollowUp; no typed attention.
- codex-dead-process-completion: a `turn.completed` whose process then died (non-zero exit, signal, or vanished) completes only if the `--output-last-message` file equals the last agent message in the retained stream; otherwise the record is consumed and the stage becomes a recoverable interruption. A requested stop reports interruption without consulting the file, and a `broken` supervisor still fails the poll.
- opencode: explicit-only (`--provider opencode --model <provider/model>`; never chosen by `--profile recommended`, never a Recommended fallback). Drives `opencode run --pure --format json -m <provider/model> [--variant <effort>] [--session <id>] --dir <worktree>`, with the prompt on immutable stdin. The model id carries the vendor (`opencode-go/deepseek-v4-pro`, `google/gemini-2.5-pro`, `opencode-go/kimi-k3`, ...); the Implementer world view colours by that vendor, not by `opencode` itself.
- opencode-native-readiness: authentication remains native, including stored credentials, provider environment variables and native provider configuration. Discovery checks native model availability, not the human-readable count printed by `auth list`: zero stored credentials does not rule out usable native providers, and ten or twenty must not be mistaken for zero. A requested model must appear in the hardened `opencode models` listing before it launches. Readiness is not a successful vendor authentication call; expired keys can still fail natively at execution.
- opencode-prompt-stdin: OpenCode v1.18.33 reads non-terminal stdin with `Bun.stdin.text()`. Initial prompts and permission/interruption continuations use Senate's immutable stdin path and digest. Prompt text does not appear in argv or environment. The existing 256 KiB composed-context limit remains a resource budget, not an `ARG_MAX` claim; optional navigation evidence yields to required context. Regression tests cover prompts exceeding Linux's 128 KiB single-argument boundary.
- opencode-permission-config: a per-invocation JSON file passed as `OPENCODE_CONFIG` records the policy. Read-only stage kinds deny edit, bash, webfetch, and external-directory access outright. Implementation/Simplification/Fix/FollowUp allow edit, still deny webfetch and external-directory access, and gate bash behind `{"*":"ask", <pattern>: "allow", ...}`. Allowed patterns are the shared Claude bash allowlist translated onto opencode's glob syntax.
- opencode-hardened-discovery (**security**): all probes, including `models` and `debug config`, receive `--pure`, `OPENCODE_DISABLE_PROJECT_CONFIG=1`, and a Senate-owned read-only config and `OPENCODE_PERMISSION`. They run in a private neutral directory with empty stdin, not the source checkout. Model listing initializes providers and plugins, so hardening only `opencode run` is too late. Discovery and execution both override `OPENCODE_CONFIG` and clear ambient `OPENCODE_CONFIG_DIR`/`OPENCODE_CONFIG_CONTENT` to keep their resolved configuration consistent and prevent a project configuration from being reintroduced indirectly. Native global configuration and per-vendor authentication variables remain available.
- opencode-agent-permission-audit (**security**): `OPENCODE_PERMISSION` wins over top-level native permissions, but **agent-specific permissions are applied after it**. Before discovery proceeds, and again before each initial, resumed or recovered launch, Senate inspects native `opencode debug config --pure` output and refuses any nonempty `permission` or legacy `tools` override under `agent` or `mode`. This covers primary agents, delegated agents and resolved Markdown agents. Invalid/unavailable configuration inspection also fails closed. Native configuration contents are not saved or included in error messages, and Senate never edits the user's configuration.
- opencode-permission-halt: headless opencode auto-rejects a `bash` "ask" it cannot interactively answer and ends the whole invocation — a clean `exit 0` whose last record is `step_finish` reason `"tool-calls"`, never `"stop"`. The adapter recovers the exact denied command from retained stdout and raises typed `needs_user` (`Permission`) attention. `resolve` (approve, no `--response`) resumes the same native session with a regenerated config that allows exactly the denied command, split into opencode's own top-level sub-commands. A decline or `--response "<text>"` resumes with that text on immutable stdin and grants nothing.
- opencode-completion-trust: opencode writes no corroborating final-message file the way Codex's `--output-last-message` does. A terminal `step_finish` (`reason: "stop"`) is trusted only on a clean process exit. An unclean exit after a stop is a recoverable interruption, never a trusted completion. A clean exit reaching neither a stop nor a permission halt fails with a specific reason.
- fake: scripted signals (start, progress, usage, attention, pause, interruption, completion, failure) without editing files; scenario `development_fake/default_success_v1`.
- verify: provider id `verify`, a deterministic command runner serving only `Role::Verifier`; routed implicitly, never chosen by `--provider` or a profile, never a provider session (see verification.md).
- permission-continuation: `resolve` reconstructs the exact denial from retained output, converts it to a native `--allowedTools` rule, and resumes the same Claude session UUID in a new managed invocation.
- artifacts: `~/.senate/runs/<run-id>/artifacts/<stage-id>.md`, SHA-256 verified before use; downstream prompts get direct dependency artifacts only.
- doctor: reports CLI versions, native readiness and suspicious configuration/credential environment variable names. The opencode `auth: ready` line means native models are available, not that a vendor request has authenticated successfully.

## How to get to it (user POV)
Install and log into `claude` and/or `codex` natively, confirm with `senate doctor`, then start runs with `--provider claude`, `--provider codex`, or Recommended. When a Claude stage stops with `needs_user`, read the attention line in `status` and answer with `resolve`. Codex has no attention path; a native denial fails the stage and you `retry`. opencode is explicit-only: install it, configure its native provider/authentication, confirm with `senate doctor`, then name it and a model (`--provider opencode --model <provider/model>`). When an opencode stage stops with `needs_user`, read the denied command and use `senate resolve <run-id> <attention-id>` to approve it, or `--response "<text>"`/`--skip` to continue without it.

**Native configuration compatibility:** opencode agent-specific permissions and legacy tools overrides are conservatively refused, even when an individual override appears restrictive. Remove those per-agent overrides before running Senate; global permission settings may remain because Senate overlays its stage policy. Native agent prompts/models are supported when they do not override permissions. Environment-based config paths/content are intentionally not honored by Senate; put required native provider settings in the normal global opencode configuration. Do not weaken the audit or enable broad permission bypass to work around a refusal.

## Driving it
```bash
senate doctor
senate fast "<task>" --provider claude
senate fast "<task>" --provider codex
senate fast "<task>" --provider opencode --model opencode-go/deepseek-v4-pro
senate fast "<task>" --provider fake
senate resolve <run-id> <attention-id>                      # approve exact permission
senate resolve <run-id> <attention-id> --response "<text>"  # answer/decline
senate retry <run-id> <stage-id> --provider opencode --model opencode-go/kimi-k3
cargo test providers::opencode
cargo test --test opencode_cli
SENATE_REAL_CLAUDE=1 cargo test --test claude_real -- --ignored --nocapture
SENATE_REAL_CODEX=1 cargo test --test codex_real -- --ignored --nocapture
SENATE_REAL_OPENCODE=1 cargo test --test opencode_real -- --ignored --nocapture
```
TUI: `u` opens the attention overlay; ↑/↓ choose the request, type an answer if it is a question, Enter resolves. The ignored native opencode smoke test consumes vendor usage; fixture and process-transport tests do not.

## Gotchas
- `permission_denials` in a Claude result is per-process, not per-session: every retry after a `--resume` gets a new `tool_use_id`. A list that looks cumulative across the resume boundary is not; treating it as residual history misclassifies a fresh attempt. Split by `tool_use_id` (`PermissionDenial::same_request`).
- "Safe to auto-approve" and "denial blocks completion" are two different policies (`exact_rule` vs `requires_terminal_attention`); when they were one function, successful results were marked infrastructure failures or `NeedsUser`. Only Edit/Write/MultiEdit/NotebookEdit, AskUserQuestion, unknown tools and denied acquisitions are terminal; a denied local Bash/Read/Glob/Grep/LS never ran, so it is not terminal.
- Mutation is not the only unfinished business a denial leaves. A denied fetch — any `mcp__*` tool, `WebFetch`/`WebSearch`, `gh`/`curl`/`git fetch` under Bash — means the evidence the stage asked for never arrived, and the stage still terminates `"subtype":"success","is_error":false`. `PermissionDenial::is_denied_acquisition` makes those terminal for every stage kind, read-only ones included; before it, run `01M1K8KAJ1HMS47H7WR8YMN2PW` ran all five stages to the end on artifacts that each said "I could not read the pull request". A denial the agent demonstrably worked around is still excused first (`was_superseded`), so this never re-strands the runs that fix healed.
- `grant_rules` decides whether an approval is worth committing and runs at `resolve`, before anything is persisted; building the resume command never refuses again (except an unanswered question). Both gates refusing is what stranded runs: a resolution committed before the gate existed leaves a session whose every later drive fails building the command, and the stage sits `running` for good with no process behind it, reachable only by a `retry` that throws the work away. A resume that can grant nothing says so in its prompt and continues; a session with no denials at all — a stopped stage picking back up — resumes plainly.
- `resume` retries a lost revision race the way `stop` does. Resuming a run something else is still driving is normal, not exceptional: the driver commits on every provider signal it observes, so the resume collides on rows it touched first and used to surface a bare revision number to the user.
- On an editing stage a denied Bash is terminal unless the invocation's own log shows the agent recovered: `protocol::superseded_requests` scans that process' stdout for a later `tool_use` of the same tool whose `tool_result` was not an error, and `PermissionDenial::was_superseded` excuses only non-mutating requests on that evidence. A refused Edit/Write or question is never excused this way, an oversized (>8 MiB) or unreadable log yields no evidence and therefore asks, and the scan moves no output cursor. Without it a run stalls on commands no rule can ever grant — a pipeline into an interpreter, a heredoc — after the agent already finished the work another way.
- The Senate never adds `--dangerously-skip-permissions`, `--yolo`, `danger-full-access`, `--ephemeral` or any Git/config bypass. Wildcard or ambiguous permission rules fail closed at `resolve`, and the refusal names why: unreadable shell, a bare redirection, or the rule-syntax character (`*`, `?`, `)`) and the part of the command carrying it.
- A question response goes to run-private stdin, never argv or SQLite event payloads.
- Claude reviewer stages are prompt-prohibited from editing but have no hard sandbox; Codex reviewers do (`read-only`). This asymmetry is documented, not patched. OpenCode's native tool permissions are not an operating-system sandbox either.
- Codex `thread.started` supplies the thread id; recovery resumes that exact id, never `--last`. A failed-stage retry creates a new session and thread.
- A retained `turn.completed` is not proof the turn finished: the same bytes survive a killed CLI. Without a clean exit, the proof is the `--output-last-message` file matching the last `item.completed` agent message byte for byte (only a trailing newline may differ, since `artifact::persist` appends it). "File exists and is non-empty" is not enough — a process killed mid-write leaves a readable prefix that would become a hash-verified half-artifact. The file is read only up to the 1 MiB artifact cap, so an oversized one fails corroboration instead of being pulled into memory. The cap counts the trailing newline `artifact::persist` appends, so a file of exactly 1 MiB fits only if it already ends in one. Uncorroborated means interruption, not an error: raising here re-reads and re-rejects the same record on every poll and pins the stage in `running` forever, reachable only by `retry`, which throws the finished work away. Recover with `senate resume <run-id>`.
- Unknown valid JSONL records become non-semantic checkpoints; an invalid complete record fails without advancing the cursor; a partial line waits.
- Claude usage comes from the terminal result record only; per-message usage is discarded on purpose.
- `--provider fake` still verifies for real: the Fake provider fakes agent roles only, and the `verify` stage runs the repository's commands regardless of the selection.
- `--provider opencode` without `--model` is refused at run creation (`AppError::OpencodeModelRequired`) before any run, workspace, or process exists. Its model id selects the vendor as well as the model.
- opencode carries the session id on every event line, unlike Codex's dedicated `thread.started`; the adapter binds (or re-confirms, on resume) native identity from whichever record happens to arrive first for an invocation, and emits `Started` only when that is the stage's very first signal — every later invocation, including a resume, reports `Resumed`.
- No runtime observation of the confirmed model or effort exists in the opencode adapter: `actual=opencode/unconfirmed` is expected even on a successful stage, not a bug.
- opencode's tokens are reported per `step_finish`, not once per turn; the adapter emits one usage delta per non-terminal step plus the terminal one, and existing read-time summation adds them up.
- The image-generation tool is a Codex CLI backend only; a role granted it but routed to opencode is a typed refusal at runtime, never a silent run without the tool.
- The generated bash allowlist inherits Claude's baseline, including `find *` and `sed *`/`awk *`. Those commands can execute code or mutate files; this review does not turn the shared baseline into an OS sandbox or a proof of read-only shell behavior.
- An exact permission grant refuses commands or split parts containing `*`, `?`, `[`, `{`, `}`, or `\`: these characters can widen native glob matching. Compound commands are checked per top-level sub-command. `command::split_top_level_commands` splits top-level `&&`/`||`/`;`/`|`/newline outside quotes/escapes and refuses uncertain quoting, command substitution, brace syntax or bare redirection. The comma-joined stderr list is never parsed as authoritative input.
- `resolve` without a response approves an opencode permission halt; any non-empty response, including `--skip`, declines and grants nothing. Decisions persist as run-private response files and are included in the resumed invocation's immutable stdin.
- Denial detection accepts native JSON error text containing "rejected permission" or "auto-reject"; stderr is not parsed as evidence.
